# ระบบแจ้งซ่อมโรงเรียนวิเชียรชม (เวอร์ชัน Firebase)

ระบบนี้เก็บข้อมูลหลักไว้ใน **Firebase Firestore** ทำให้เปิดรายการได้เร็วและอัปเดตอัตโนมัติ
ส่วน **Google Apps Script** ทำหน้าที่เก็บไฟล์ลง Google Drive คือ รูปภาพ แบบฟอร์มแจ้งซ่อม (PDF) และ Backup ข้อมูลทุกวัน

```
ครูแจ้งซ่อม ──► index.html ──► Firestore (ข้อมูลหลัก, เรียลไทม์)
                    └─ รูป ─────────► Apps Script ─► Drive: รูปภาพแจ้งซ่อม/
เจ้าหน้าที่ ──► admin.html (ล็อกอิน Google) ──► อัปเดตสถานะ / ตั้งผู้ลงนามแทน
                    └─ PDF (ดำเนินการ / เสร็จสิ้น) ─► Apps Script ─► Drive: แบบฟอร์มแจ้งซ่อม/
ทุกวันตี 2 ──► Apps Script อ่าน Firestore ─► Drive: Backup/ (Google Sheet + JSON)
พิมพ์เอกสาร ──► print.html ──► บันทึกข้อความแจ้งซ่อม (แบบงานทั่วไป / แบบงานไอที)
```

โฟลเดอร์ใน Google Drive

```
ระบบแจ้งซ่อม/
├─ รูปภาพแจ้งซ่อม/2026-11/...jpg
├─ แบบฟอร์มแจ้งซ่อม/2026-11/0005 นางสาวสมใจ ใจดี.pdf
└─ Backup/  (Google Sheet + backup-ปี-เดือน-วัน.json)
```

## ขั้นที่ 1 — สร้างโปรเจกต์ Firebase (ประมาณ 10 นาที)

> ใช้บัญชี Google ที่จะดูแลระบบระยะยาว และใช้บัญชีเดียวกันนี้ในขั้นที่ 3 ด้วย
> บัญชีโรงเรียนที่ถูกตั้งเป็น "อายุต่ำกว่า 18 ปี" จะเปิด Firebase และ Apps Script ไม่ได้ ให้ใช้ Gmail ส่วนตัวแทน แล้วให้ไฟล์ไปอยู่ในไดรฟ์โรงเรียนได้ตามขั้นที่ 3 ข้อ 0

1. เข้า <https://console.firebase.google.com> → **Create a project** → ตั้งชื่อ เช่น `wichianchom-repair` (ไม่ต้องเปิด Google Analytics)
2. **สร้างฐานข้อมูล:** เมนู Build → **Firestore Database** → Create database
   - Location: เลือก **`asia-southeast1` (Singapore)** หรือ region ที่ใกล้ไทยที่สุดในรายการ เพื่อให้ระบบเร็ว *(เปลี่ยนภายหลังไม่ได้)*
   - เลือก **Start in production mode**
3. **ใส่กฎความปลอดภัย:** Firestore Database → แท็บ **Rules** → ลบของเดิม แล้ววางเนื้อหาไฟล์ `firestore.rules` ทั้งไฟล์ → **Publish**
4. **เปิดล็อกอินด้วย Google:** Build → **Authentication** → Get started → แท็บ Sign-in method → **Google** → Enable → เลือกอีเมลติดต่อ → Save
5. **เอาค่าตั้งค่ามาใส่เว็บ:** ⚙️ Project settings → ส่วน Your apps → กดไอคอน **`</>`** (Web) → ตั้งชื่อแอป → Register
   - จะเห็นโค้ด `firebaseConfig = { apiKey: ..., authDomain: ..., ... }`
   - คัดลอกค่าทั้ง 6 ตัวไปใส่ในส่วน `firebase:` ของ `js/config.js`
   - ค่าชุดนี้ **เปิดเผยได้ตามปกติ** ความปลอดภัยของระบบอยู่ที่ `firestore.rules`

1. Firestore Database → แท็บ Data → **Start collection** → Collection ID: `admins`
2. Document ID: **อีเมล Google ของเจ้าหน้าที่ ตัวพิมพ์เล็กทั้งหมด** เช่น `somchai@gmail.com`
3. เพิ่ม field อะไรก็ได้ 1 ช่อง เช่น `name` (string) = `นายสมชาย` → Save
4. ทำซ้ำสำหรับเจ้าหน้าที่ทุกคน และลบ document ออกเมื่อต้องการถอนสิทธิ์

> รหัสผ่าน `admin123` แบบเดิมถูกยกเลิกแล้ว เจ้าหน้าที่ต้องล็อกอินด้วยบัญชี Google ที่มีชื่ออยู่ในรายการนี้เท่านั้น

## ขั้นที่ 3 — ติดตั้ง Apps Script (เก็บรูป + แบบฟอร์ม + Backup)

> ติดตั้งด้วย **บัญชีเดียวกับที่สร้าง Firebase** (อีเมลส่วนตัว) ถ้าอยากให้รูปและ Backup ไปอยู่ในไดรฟ์ของอีเมลโรงเรียน ให้ทำข้อ 0 ก่อน
> ทำในหน้าต่างที่ล็อกอินบัญชีนี้บัญชีเดียว (เช่น Incognito) เพราะถ้าล็อกอินหลายบัญชีพร้อมกัน Apps Script มักสับสนบัญชี

0. **(ถ้าต้องการ) ให้ไฟล์ไปอยู่ในไดรฟ์ของอีเมลโรงเรียน**
   - ล็อกอินอีเมลโรงเรียน → Google Drive → **สร้างโฟลเดอร์ใหม่** เช่น `ระบบแจ้งซ่อม`
   - คลิกขวาโฟลเดอร์ → **แชร์** → ใส่อีเมลส่วนตัว → สิทธิ์ **ผู้แก้ไข (Editor)** → ส่ง
   - คลิกขวาโฟลเดอร์อีกครั้ง → แชร์ → **คัดลอกลิงก์** เก็บไว้ใช้ในข้อ 2
   - รูป แบบฟอร์ม และ Backup จะแสดงในโฟลเดอร์นี้ของอีเมลโรงเรียน แต่ Google จะนับอีเมลส่วนตัวเป็นเจ้าของไฟล์ (ใช้พื้นที่ของอีเมลส่วนตัว รูปละราว 0.3 MB แบบฟอร์มละราว 0.5 MB)
   - ถ้าแชร์ไม่ได้เพราะโรงเรียนห้ามแชร์ไฟล์ให้คนนอกองค์กร ให้ข้ามข้อนี้ไป ไฟล์จะเก็บใน Drive ของอีเมลส่วนตัวแทน
1. เข้า <https://script.google.com> → New project → ตั้งชื่อ เช่น `ระบบแจ้งซ่อม - รูปและ Backup`
2. ลบโค้ดเดิมใน `Code.gs` แล้ววางเนื้อหาไฟล์ `apps-script/Code.gs` ทั้งไฟล์
   - ถ้าทำข้อ 0 ให้วางลิงก์โฟลเดอร์ในบรรทัด `const DRIVE_FOLDER = '';` เช่น `const DRIVE_FOLDER = 'https://drive.google.com/drive/folders/xxxx';`
3. ตรวจบรรทัด `FIREBASE_PROJECT_ID` และ `FIREBASE_API_KEY` ให้ตรงกับ `projectId` และ `apiKey` จากขั้นที่ 1 (ใส่ไว้ให้แล้ว)
4. ⚙️ Project Settings → ติ๊ก **Show "appsscript.json" manifest file in editor** → กลับไปหน้า Editor → เปิด `appsscript.json` → วางเนื้อหาไฟล์ `apps-script/appsscript.json` ทับ → Save
4.1 **ใส่กุญแจ Service Account** (ให้ Apps Script อ่านข้อมูล Firebase ได้ ใช้ทั้ง Backup และบันทึกแบบฟอร์ม)
   - Firebase Console → ⚙️ Project settings → แท็บ **Service accounts** → ปุ่ม **Generate new private key** → Generate key → ได้ไฟล์ `.json` มา 1 ไฟล์
   - เปิดไฟล์นั้นด้วย Notepad → Ctrl+A → Ctrl+C
   - Apps Script → ⚙️ Project Settings → เลื่อนลงล่างสุด **Script Properties** → **Add script property** → Property: `SERVICE_ACCOUNT` → Value: วาง (Ctrl+V) → **Save script properties**
   - ลบไฟล์ `.json` ที่ดาวน์โหลดออกจากเครื่อง และห้ามส่งให้ใคร (กุญแจนี้มีสิทธิ์เต็มในฐานข้อมูล)
5. ด้านบนเลือกฟังก์ชัน **`setup`** → กด **Run** → Review permissions → เลือกบัญชี → Advanced → Go to ... (unsafe) → **Allow**
   - ดู Execution log ต้องเห็น "🔑 เชื่อม Firebase ด้วย Service Account", ✅ หลายบรรทัด และ "ติดตั้งเสร็จ"
   - ระบบจะสร้างโฟลเดอร์ "รูปภาพแจ้งซ่อม", "แบบฟอร์มแจ้งซ่อม", "Backup" และ Google Sheet สำรองข้อมูล ไว้ในโฟลเดอร์จากข้อ 0 (หรือในโฟลเดอร์ใหม่ชื่อ "ระบบแจ้งซ่อม (Firebase)" ใน Drive ของบัญชีนี้ ถ้าไม่ได้ใส่ `DRIVE_FOLDER`)
   - ถ้าเปลี่ยน `DRIVE_FOLDER` ภายหลัง ให้รัน `setup` อีกครั้ง
6. **Deploy → New deployment** → ไอคอนเฟือง → **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
   - กด Deploy → คัดลอก **Web app URL** (ลงท้ายด้วย `/exec`) ไปใส่ที่ `appsScriptUrl` ใน `js/config.js`

> ถ้าแก้โค้ด Apps Script ภายหลัง ให้ไปที่ Deploy → Manage deployments → ✏️ Edit → Version: **New version** → Deploy (URL จะเหมือนเดิม)

## การ Backup และกู้ข้อมูล

| ที่เก็บ | รายละเอียด |
|---|---|
| Google Sheet "Backup ระบบแจ้งซ่อม" | เขียนทับทุกวันตอนตี 2 อ่านง่าย เปิดดูหรือกรองได้ทันที |
| ไฟล์ `backup-ปี-เดือน-วัน.json` | สร้างใหม่ทุกวัน เก็บย้อนหลัง 30 ไฟล์ มีข้อมูลครบทุกช่อง ใช้กู้คืนได้ |
| โฟลเดอร์ "รูปภาพแจ้งซ่อม" | รูปทั้งหมด แยกโฟลเดอร์ตามเดือน |

- มุมขวาล่างของหน้าเจ้าหน้าที่จะแสดงเวลาที่ Backup ครั้งล่าสุด
- ปุ่ม **ดาวน์โหลด CSV** ในหน้าเจ้าหน้าที่ใช้ดึงข้อมูลทั้งหมดเปิดใน Excel ได้ทุกเมื่อ
- ข้อมูลเก่าใน Google Sheet ของระบบเดิมยังอยู่ครบ ระบบใหม่เริ่มนับเลขที่จาก 1

## โควตาฟรีของ Firebase (แพ็กเกจ Spark ไม่ต้องผูกบัตร)

- อ่านข้อมูลได้วันละ 50,000 ครั้ง เขียนได้วันละ 20,000 ครั้ง เก็บข้อมูลได้ 1 GB
- การเปิดหน้ารายการหนึ่งครั้งอ่านไม่เกิน 60 รายการ (ปรับได้ที่ `publicPageSize`) จึงรองรับการเปิดได้หลายร้อยครั้งต่อวัน
- โควตารีเซ็ตทุกเที่ยงคืนเวลาแปซิฟิก (ประมาณบ่าย 2–3 โมงเวลาไทย) ดูการใช้งานได้ที่ Firestore → Usage
- ระบบไม่ใช้ Cloud Storage ของ Firebase (ต้องใช้แพ็กเกจเสียเงิน) จึงเก็บรูปไว้ใน Google Drive แทน

## ใบแจ้งซ่อมที่พิมพ์ออกมา

- **พิมพ์ได้เมื่อเจ้าหน้าที่ตรวจสอบแล้วเท่านั้น** คือสถานะเป็น "ดำเนินการ" หรือ "เสร็จสิ้น" ระหว่าง "รอการตรวจสอบ" ปุ่มพิมพ์จะขึ้นเป็น 🔒 ทั้งงานทั่วไปและงานไอที
  - **งานไอที** ต้องกรอก "ความคิดเห็นของเจ้าหน้าที่" ก่อนเปลี่ยนเป็น "ดำเนินการ" เพราะแบบฟอร์มมีช่องนี้ และจะพิมพ์ลงในใบ
  - **งานทั่วไป** ไม่ต้องลงความเห็น (แบบฟอร์มไม่มีช่องนี้) ช่องความเห็นในหน้าเจ้าหน้าที่ใช้จดไว้ในระบบเท่านั้น

- ใช้ **แบบฟอร์มบันทึกข้อความต้นฉบับของโรงเรียน** (ไฟล์ PDF) เป็นพื้นหลังทั้งหน้า แล้วกรอกข้อมูลทับบนเส้นประ หน้าตาจึงเหมือนต้นฉบับทุกจุด
  - งานทั่วไป ใช้แบบหน้าแรกของไฟล์ / งานไอที ใช้แบบหน้าที่สอง
  - ช่องลงนาม **งานทั่วไป**: กลุ่มบริหารงานทั่วไป → เจ้าหน้าที่พัสดุ → กลุ่มบริหารงบประมาณ → ผู้อำนวยการ
  - ช่องลงนาม **งานไอที** (ฉบับ 17 พ.ย. 2569): ความเห็นช่างคอมพิวเตอร์/เทคโนโลยี → กลุ่มบริหารงานทั่วไป → เจ้าหน้าที่พัสดุ → ผู้อำนวยการ (ไม่มีช่องกลุ่มบริหารงบประมาณ)
  - ตัวอักษรที่กรอกใช้ TH SarabunIT๙ ถ้าเครื่องติดตั้งไว้ ถ้าไม่มีใช้ TH Sarabun New ซึ่งเป็นแบบอักษรเดียวกันและขนาดเท่ากันทุกตัว ตัวเลขแสดงเป็นเลขไทยแบบ TH SarabunIT๙
  - ข้อความยาวเกินช่องจะย่อขนาดตัวอักษรลงให้พอดีช่องอัตโนมัติ
- แบบฟอร์มมีช่องรายการ 2 ช่อง หน้าแจ้งซ่อมจึงรับได้สูงสุด 2 รายการ
- **แผ่นที่ 2** เป็นภาพประกอบ มีหัวกระดาษบอกเลขที่ ผู้แจ้ง กลุ่มงาน สถานที่ และวันที่แจ้ง (ทั้งงานทั่วไปและงานไอที) เลือกไม่พิมพ์ได้ที่แถบด้านบนของหน้าพิมพ์
- **สถานที่** ไม่มีช่องในแบบฟอร์ม จึงแสดงไว้ที่หัวกระดาษแผ่นที่ 2 แทน
- ถ้าโรงเรียนเปลี่ยนแบบฟอร์ม ให้ส่งไฟล์ PDF ใหม่มาทำพื้นหลังและตำแหน่งช่องใหม่ (ตำแหน่งช่องอยู่ที่ `LAYOUT` ใน `print.html`)

## แบบฟอร์มแจ้งซ่อม (PDF) ใน Drive

- สร้างอัตโนมัติเมื่อเจ้าหน้าที่บันทึกสถานะ **"ดำเนินการ"** หรือ **"เสร็จสิ้น"** และสร้างใหม่ทับไฟล์เดิมทุกครั้งที่บันทึก ไฟล์จึงตรงกับข้อมูลล่าสุดเสมอ (ไฟล์เก่าจะอยู่ในถังขยะ 30 วัน)
- กดเองได้ที่หน้าต่างจัดการงาน → "📄 แบบฟอร์มใน Drive" → **บันทึกลง Drive / อัปเดตไฟล์**
- **ไฟล์ที่บันทึกไว้ก่อนเปลี่ยนแบบฟอร์ม** หน้าเจ้าหน้าที่จะขึ้นแถบสีฟ้า "มีไฟล์ใบแจ้งซ่อมใน Drive … ไฟล์ ที่ยังเป็นแบบฟอร์มเก่า" กด **อัปเดตเป็นแบบฟอร์มปัจจุบันทั้งหมด** ระบบจะสร้างไฟล์ใหม่แทนทีละใบ (ไฟล์เก่าอยู่ในถังขยะ 30 วัน)
  - ถ้าแก้หน้าตาใบแจ้งซ่อมอีกในอนาคต ให้เปลี่ยนค่าของประเภทนั้นใน `FORM_VERSIONS` ใน `js/common.js` แถบนี้จะขึ้นให้อัปเดตเฉพาะไฟล์ของประเภทนั้น
  - ใบที่เปลี่ยนประเภทงานหลังบันทึก PDF แล้ว ก็จะถูกนับว่าเป็นแบบเก่าและอัปเดตให้ด้วย
  - การกด "พิมพ์" ใช้แบบฟอร์มปัจจุบันเสมอ ไม่ต้องอัปเดตอะไร
- ไฟล์ PDF เป็นภาพของบันทึกข้อความ 1 หน้า (เหมือนที่พิมพ์ออกมา) ไม่รวมรูปถ่าย เพราะรูปเก็บแยกอยู่ในโฟลเดอร์ "รูปภาพแจ้งซ่อม" แล้ว
- ส่งได้เฉพาะเจ้าหน้าที่ที่ล็อกอินแล้ว Apps Script ตรวจตัวตนกับ Firebase และตรวจรายชื่อใน `admins` ทุกครั้ง

## เปลี่ยนผู้ลงนาม / ผู้ปฏิบัติหน้าที่แทน

หน้าเจ้าหน้าที่ → ปุ่ม **✍️ ผู้ลงนาม**

- **ชื่อผู้ลงนามปกติ** — แก้ได้ทันทีเมื่อมีการเปลี่ยนตัวบุคคล ไม่ต้องแก้ไฟล์
- **มีผู้ปฏิบัติหน้าที่แทน** — ติ๊กแล้วกรอกชื่อผู้แทน ข้อความ (ช่องผู้อำนวยการ: แสดงแทนบรรทัดตำแหน่งใต้ชื่อ เช่น "รักษาราชการแทนผู้อำนวยการโรงเรียนวิเชียรชม" / ช่องอื่น: แสดงต่อท้ายชื่อ เช่น "ปฏิบัติหน้าที่แทน") และช่วงวันที่
  - ใบแจ้งซ่อมที่ **ลงวันที่ในช่วงนั้น** จะพิมพ์ชื่อผู้แทนอัตโนมัติ ใบที่ลงวันที่นอกช่วงยังใช้ชื่อปกติ แม้จะพิมพ์ซ้ำภายหลัง
  - ไม่ใส่วันที่ = ใช้ผู้แทนกับทุกใบจนกว่าจะเอาเครื่องหมายถูกออก
  - ระหว่างที่มีผู้แทน หน้าเจ้าหน้าที่จะมีแถบสีม่วงแจ้งไว้
- **เปลี่ยนเฉพาะใบ** — ในหน้าต่างจัดการงาน → "✍️ ผู้ลงนามในใบนี้" กรอกเฉพาะช่องที่ต้องการเปลี่ยน แล้วกดบันทึก (แสดงเฉพาะช่องที่มีในแบบฟอร์มของประเภทงานนั้น)
- ช่องกลุ่มบริหารงบประมาณมีเฉพาะใบงานทั่วไป ในหน้าตั้งผู้ลงนามจะมีป้าย "(เฉพาะใบงานทั่วไป)" กำกับไว้

## ความปลอดภัย

- คนทั่วไปทำได้แค่ดูรายการและแจ้งซ่อมใหม่ ข้อมูลที่ส่งเข้ามาจะถูกตรวจรูปแบบทุกครั้งตาม `firestore.rules`
- **เบอร์โทรและหมายเหตุภายใน** เก็บแยกไว้ และเห็นได้เฉพาะเจ้าหน้าที่
- ข้อความที่ผู้ใช้กรอกถูกแสดงแบบป้องกันการฝังโค้ด (XSS) ทุกจุด
- Apps Script รับเฉพาะไฟล์รูป จำกัดขนาด และจำกัดจำนวนการอัปโหลดต่อ 10 นาที ส่วนแบบฟอร์ม PDF รับเฉพาะจากเจ้าหน้าที่ที่ยืนยันตัวตนแล้ว
- รายชื่อผู้ลงนามแก้ได้เฉพาะเจ้าหน้าที่

## ปรับแต่งที่ `js/config.js`

- `staff` — รายชื่อช่างแยกตามประเภทงาน
- `approvers` — หัวข้อและตำแหน่งในช่องลงนาม (ส่วน **ชื่อ** ให้แก้ที่ปุ่ม "✍️ ผู้ลงนาม" ในหน้าเจ้าหน้าที่)
- `techSection` — ช่องความเห็นของช่าง/เจ้าหน้าที่ผู้รับผิดชอบ แบบฟอร์มงานทั่วไปเดิมไม่มีช่องนี้ ระบบเพิ่มไว้ให้เพื่อพิมพ์ผลการซ่อม ถ้าไม่ต้องการให้ลบบรรทัด `General: {...}` ออก
- `publicPageSize`, `adminPageSize` — จำนวนรายการที่โหลดต่อครั้ง

## แก้ปัญหาที่พบบ่อย

**หน้าเว็บขึ้น "ไม่มีสิทธิ์เข้าถึงข้อมูล"**
ยังไม่ได้ Publish `firestore.rules` (ขั้นที่ 1 ข้อ 3) หรือวางไฟล์ไม่ครบ

**หน้าเจ้าหน้าที่ขึ้น "โดเมนนี้ยังไม่ได้รับอนุญาต"**
เพิ่มโดเมนเว็บใน Authentication → Settings → Authorized domains

**ล็อกอินแล้วขึ้น "ยังไม่มีสิทธิ์เจ้าหน้าที่"**
Document ID ใน collection `admins` ต้องเป็นอีเมลตรงกันทุกตัวอักษร และเป็นตัวพิมพ์เล็กทั้งหมด

**อัปโหลดรูปไม่สำเร็จ**
- ตรวจว่า Deploy แบบ Web app โดยตั้ง Who has access เป็น **Anyone** และใช้ URL ที่ลงท้ายด้วย `/exec`
- ถ้าเพิ่งแก้โค้ด ต้อง Deploy เป็น **New version**
- ถ้ารัน `setup` แล้วขึ้น "เปิดโฟลเดอร์ใน DRIVE_FOLDER ไม่ได้" ให้ตรวจว่าวางลิงก์ถูก และอีเมลโรงเรียนแชร์โฟลเดอร์ให้อีเมลส่วนตัวเป็น "ผู้แก้ไข" แล้ว

**บันทึกแบบฟอร์มลง Drive ไม่สำเร็จ**
- "ต้องอัปเดตโค้ด Apps Script..." → วาง `Code.gs` ชุดใหม่ แล้ว Deploy → Manage deployments → ✏️ → Version: **New version**
- "ยืนยันตัวตนไม่สำเร็จ" → ตรวจ `FIREBASE_API_KEY` ใน `Code.gs` ให้ตรงกับ `apiKey` ใน `js/config.js` แล้วออกจากระบบและเข้าใหม่
- "บัญชีนี้ไม่มีสิทธิ์เจ้าหน้าที่" → อีเมลยังไม่อยู่ใน collection `admins`

**กดปุ่ม "✍️ ผู้ลงนาม" แล้วบันทึกไม่ได้ (ไม่มีสิทธิ์)**
วาง `firestore.rules` ชุดใหม่ (มีส่วน `settings`) แล้วกด Publish

**Backup ไม่ทำงาน (มุมขวาล่างหน้าเจ้าหน้าที่ขึ้น ⚠️)**
เปิด Apps Script → Executions เพื่อดูข้อความผิดพลาด
- `403 Missing or insufficient permissions` + "ตั้งค่า SERVICE_ACCOUNT" → ยังไม่ได้ใส่กุญแจ ทำขั้นที่ 3 ข้อ 4.1
- "SERVICE_ACCOUNT ไม่ถูกต้อง" → วางเนื้อหาไฟล์ `.json` ไม่ครบ ให้ลบ property เดิมแล้ววางใหม่ทั้งไฟล์
- "ขอสิทธิ์จาก Service Account ไม่สำเร็จ" → กุญแจถูกลบใน Firebase ให้สร้างกุญแจใหม่แล้ววางทับ
- `404` → ยังไม่ได้สร้าง Firestore Database หรือ `FIREBASE_PROJECT_ID` ไม่ถูกต้อง

**พิมพ์แล้วไม่ตรงกระดาษ**
ในหน้าต่างพิมพ์ให้เลือกกระดาษ **A4**, Scale **100%** (หรือ "ค่าเริ่มต้น") และระยะขอบ **ไม่มี / None** ถ้าเลือก "พอดีกับหน้า (Fit to page)" แบบฟอร์มจะถูกย่อลง
